## 2. Audit

| Question | Answer |
|---|---|
| Engine and version | Godot 4. Built and tested on **4.5.1 stable**. `project.godot` asks for 4.3 or newer. I could not check for a newer release: godotengine.org is refused by this environment's network rules |
| Bundler or single file | Neither: a Godot project. No external libraries or add-ons, so nothing else to pin |
| Renderer | Forward+ in the project settings. **See decision 1 below** |
| How the UI is drawn | Godot `Control` nodes built in code, one script per panel, under one `CanvasLayer` (`scenes/ui/hud.tscn`). Nameplates and damage numbers are drawn in `_draw()` from projected 3D positions |
| Where models are made | All in code from primitives. Until this pass that code lived in four scripts; it now sits behind the asset manifest (section 5) |
| The cave | A scene generated by `tools/build_sealed_cave.py` from a map of 2 m cells; boxes for floors and walls |
| How time is stepped | Godot's main loop: `_physics_process` at 60 Hz for movement and combat, `_process` for presentation. `Engine.time_scale` is used once, for slow motion at death |
| Automated regression | Ten headless test scenes, 336 checks (`tools/run_tests.sh`) |

## 5. What changed in the game

- **Models come through the manifest.** The slime, Veldora, his seal, the
  five monsters and their Mimicry forms, herbs, ore and motes are asked for by
  id from `Assets`. Each manifest entry names a stand-in builder; the builders
  are the old model code, moved unchanged into `scripts/visual/stand_ins.gd`.
  A manifest entry that names a file loads it, scales it to the entry's height
  and rests it on the floor. A named file that is missing shows the stand-in
  and logs one warning.
- **The level's look comes from the config:** linear tone mapping, bloom at a
  threshold of 1 so only emissive surfaces glow, a colour grade (neutral for
  now), 2x multisampling, and fog and background in the palette's cave fog
  colour instead of near-black. A tinted vignette sits under the HUD.
- **Nothing else.** Bindings, damage, timings, colliders and interaction
  positions are untouched.

The one visible difference is the fog: distance now fades to violet rather
than to black, as rule S7 asks. Compare `before/` with `pass_0/`.

## 8. Decisions I need from you

**Answered** (and applied at the start of [Pass 1](PASS_1.md)): 1, switch to
the Compatibility renderer; 2, option (a), keep both wisdom cards and word the
second as the step up; 3, the slime's face is on by default.

1. **Renderer.** I can only render with Godot's Compatibility renderer here;
   the Forward+ renderer needs Vulkan, which this environment lacks. Every
   screenshot I check is therefore Compatibility, while the project is set to
   Forward+. Bloom strength, fog and light falloff differ between the two.
   My recommendation is to switch the project to Compatibility for this
   overhaul: a toon look needs nothing Forward+ offers, it is lighter, and
   what I verify is then what you see. I have not changed it. If you would
   rather stay on Forward+, I will keep every shader valid in both and you
   check the screenshots on your machine after each pass.
2. **"Two cards giving the identical result" (section 14.4).** The cause is
   the game design itself, not a bug in dealing: two different thoughts
   ("If only I had understood..." and "There was so much I never worked
   out.") both grant Sage, and holding both upgrades it to Great Sage, which
   is the design document's "second wisdom card". Making results unique within
   a hand would remove that. Options for Pass 7: (a) keep both and word the
   second so the pair reads as an upgrade, (b) keep one wisdom card that
   grants Sage and let a second copy of it appear only as "Great Sage",
   (c) dedupe and drop the upgrade. I suggest (a).
3. **Slime face.** Section 5 puts eyes behind a switch. Tell me the default
   you want; I will build both.
4. **Lock-on key** (section 13) and the **humanoid route** (section 8) can
   wait until their passes.

Confirmed and scheduled, no decision needed: the message log and status box
showing through the last-thoughts panel is real (bookmark 8) and is fixed by
the modal manager in Pass 7.
